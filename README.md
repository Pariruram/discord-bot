# Discord AI Bot

Discord-бот с LLM-чатом, долговременной памятью пользователей и каналов,
веб-поиском и подключаемыми инструментами.

## Возможности

- ответы в ЛС и по упоминанию в каналах;
- память в разрезе ЛС, канала и ветки: бот не смешивает собеседников;
- факты о пользователях, резюме сессий и общие резюме разговоров в Supabase;
- ответы бота тоже сохраняются в память;
- догоняющая синхронизация сообщений после перезапуска Render;
- смена LLM-провайдера и модели командами, без рестарта;
- `!models` — кнопки с free-моделями, доступна всем;
- произвольные OpenAI-совместимые провайдеры;
- инструменты (tools) с включением/отключением из чата;
- автоматические ссылки на источники при веб-поиске;
- понятные ошибки LLM с подсказками по модели и ключу;
- health-check сервер для Render / Hugging Face Spaces.

## Установка

Требуется Python 3.11+.

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
pip install -r requirements.txt
copy .env.example .env
```

Заполни `.env`:

| Переменная | Обязательно | Назначение |
|---|---|---|
| `DISCORD_TOKEN` | да | токен бота |
| `SUPABASE_URL` | да | URL проекта Supabase |
| `SUPABASE_KEY` | да | service/anon key с доступом к таблицам |
| `GEMINI_API_KEY` | для Gemini | ключ провайдера |
| `GROQ_API_KEY` | для Groq | ключ провайдера |
| `OPENAI_API_KEY` | для OpenAI | ключ провайдера |
| `OPENROUTER_API_KEY` | для OpenRouter | ключ провайдера |
| `TAVILY_API_KEY` | для веб-поиска | ключ Tavily |
| `PORT` | нет | порт health-сервера (по умолчанию 7860) |
| `ENABLE_HEALTH` | нет | `false` отключает health-сервер |
| `LOG_LEVEL` | нет | уровень логирования |

Запуск:

```bash
python main.py
```

## Таблицы Supabase

Схема памяти: `supabase/migrations/20261108000100_memory.sql`. Примени её один
раз в SQL Editor (или через `supabase db push`). Если схема уже была применена
до фиксов, дополнительно примени:
`20261108000200_fix_ingest_message.sql` и
`20261108000300_fix_history_before.sql`.

- `bot_settings` — настройки бота;
- `users` — память включена/выключена и время активности;
- `user_personas` — стиль общения и заметка владельца;
- `user_facts` — долговременные факты с видимостью `private`/`public`;
- `conversations` — ЛС, канал или ветка;
- `conversation_sessions` — сессии с разрывом `session_gap_minutes`;
- `conversation_summaries` — резюме сессий и разговоров;
- `messages` — все сообщения с автором, ролью и адресатом;
- `memory_jobs` — очередь фоновых задач, переживает рестарт Render.

Старые таблицы `user_profiles`, `chat_history`, `channel_context` кодом больше
не используются. Их можно удалить вручную после проверки нового деплоя.

Память работает в пределах одной беседы: ЛС не видит каналы, канал не видит
другие каналы, ветка не смешивается с родительским каналом. Факты одного
пользователя никогда не попадают в контекст другого. В канале бот видит только
факты с `visibility=public`, в ЛС — все факты владельца диалога.

### Настройки памяти

Все параметры задаются через `!set` и хранятся в `bot_settings`; новых
переменных окружения нет.

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `memory_enabled` | `true` | глобальное включение памяти |
| `memory_retention_days` | `365` | срок хранения сообщений |
| `max_facts_per_user` | `200` | предел фактов на пользователя |
| `max_context_facts` | `20` | сколько фактов подмешивать в ответ |
| `session_gap_minutes` | `30` | пауза, после которой сессия закрывается |
| `worker_poll_seconds` | `30` | период опроса очереди |
| `worker_llm_interval_seconds` | `6` | минимальная пауза между LLM-вызовами worker |
| `catch_up_limit` | `100` | сколько сообщений догонять после рестарта |
| `allowed_channel_ids` | `[]` | каналы, где бот помнит и фоновые сообщения |
| `max_history` | `100` | сообщений в контексте ответа (до 1000) |
| `max_context_chars` | `40000` | символьный бюджет транскрипта и диалога ЛС (до 400000) |
| `debug_mode` | `false` | фактическая строка с моделью, инструментами и контекстом после ответа |
| `auto_links` | `true` | автоматически читать ссылку из короткого сообщения |
| `auto_links_max` | `1` | сколько ссылок читать автоматически (1–3) |
| `svg_model` | текущая модель | модель, которая рисует SVG (например, `gemini-3.5-flash-lite`) |
| `svg_cooldown_seconds` | `15` | пауза между рисунками одного пользователя (0–600) |
| `pixel_grid` | `32` | сетка пиксель-арта: 16, 32, 64 или 128 |
| `pixel_colors` | `16` | палитра пиксель-арта (8–32 цвета) |
| `pixel_palette` | `auto` | палитра пиксель-арта: `auto` или имя из `!palette` |
| `search_max_results` | `5` | сколько источников искать, если модель не указала число (1–10) |
| `max_tokens` | `1200` | лимит ответа модели |

Если `allowed_channel_ids` пуст, бот запоминает только те сообщения, которые
адресованы ему (упоминание, ответ или ЛС). Укажи ID двух каналов, чтобы бот
хранил и контекст обычной переписки:

```
!set allowed_channel_ids 123456789012345678,987654321098765432
```

В каналах вне списка бот не отвечает и ничего не запоминает. Личные сообщения
работают всегда.

Ответ собирается из последних `max_history` сообщений беседы, последнего общего
резюме и до трёх резюме сессий. Если `allowed_channel_ids` пуст, в эти последние
сообщения попадут только обращения к боту; чтобы контекст канала был полным,
добавь канал в список.

## Команды

### Для всех

| Команда | Описание |
|---|---|
| `!models` | кнопки с доступными free-моделями; выбор глобальный для всех |

`!models` показывает только free-модели, для которых у провайдера настроен
API-ключ (или ключ не требуется). Дубликаты убираются. Выбранная модель
применяется для всех участников — это удобно для небольшого чата.

### Память

| Команда | Описание |
|---|---|
| `!memory` | что бот помнит о тебе и включена ли память |
| `!memory on` / `!memory off` | включить или выключить память |
| `!forget <id>` | удалить один факт |
| `!forget all` | удалить все факты о тебе |

Команды работают только в личных сообщениях с ботом. Выключение памяти
останавливает сохранение новых сообщений; старые факты удаляются через
`!forget all`.

### Только ЛС владельца

| Команда | Описание |
|---|---|
| `!owners` | список владельцев |
| `!owner add <id>` / `!owner remove <id>` | управление владельцами |
| `!settings` | все настройки |
| `!set <key> <value>` | изменить настройку |
| `!system [set <text>\|reset]` | system prompt |
| `!model` | текущая модель и провайдеры |
| `!model provider:model` | глобально переключить провайдера и модель |
| `!model model` | сменить модель у текущего провайдера |
| `!provider list` | список провайдеров |
| `!provider add <name> <base_url> <KEY_ENV\|-> <model> [utility_model]` | добавить OpenAI-совместимый провайдер |
| `!provider remove <name>` | удалить кастомный провайдер |
| `!tools` | список инструментов |
| `!tools enable <name>` / `!tools disable <name>` | включить/отключить инструмент |

Примеры:

```
!models
!model groq:openai/gpt-oss-120b
!model gemini:gemini-3.8-flash
!provider add local http://localhost:11434/v1 - llama3.1
!model local:llama3.1
```

`chat_model` — основная модель для ответов и tool-calling.
`utility_model` — быстрая модель для извлечения фактов и резюме памяти; она
должна принадлежать тому же провайдеру, что и `chat_model`, и стабильно
возвращать JSON. Если в логах есть `Не удалось разобрать JSON фактов`, смени
`utility_model` через `!set utility_model <model>`.

При смене модели через `!models` обе настройки обновляются автоматически.
`!model` у владельца остаётся аварийным способом поставить произвольную модель.

Владельцы хранятся в `bot_settings.owners` (JSON-список). Первого владельца
нужно добавить вручную в БД.

Фоновая память работает внутри веб-процесса: Render free не даёт отдельных
workers. Очередь лежит в `memory_jobs`, поэтому задачи не теряются при
перезапуске или засыпании сервиса. Раз в 30 секунд воркер опрашивает очередь
(это же не даёт бесплатному Supabase уснуть), закрывает неактивные сессии,
извлекает факты и сворачивает резюме. Если пауза в разговоре превысила
`session_gap_minutes`, новая сессия открывается сразу в SQL, а закрытая
сессия всё равно получает резюме при следующем проходе воркера. Сообщения
после офлайна догоняются через `channel.history(after=last_seen_message_id)`.
Воркер берёт по одной задаче и делает не больше одного LLM-вызова раз в
`worker_llm_interval_seconds`, чтобы не упираться в лимиты free tier.
Временные `503`/`429` не теряют задачу: `fail_job` возвращает её в `pending`
с задержкой 5 минут (до 3 попыток), а в лог пишется `WARNING` с номером
попытки без traceback. После третьей неудачи задача помечается `failed`.

Инструменты по умолчанию: `web_search`, `fetch_url`, `draw_svg`, `read_thread`.

### Чтение ссылок и YouTube

`fetch_url` открывает конкретную ссылку из сообщения и возвращает модели
читаемый текст: заголовок, описание и содержимое статьи/документации. Если
ссылка — суть короткого сообщения (или пользователь отвечает на сообщение со
ссылкой), бот читает её **автоматически, до ответа модели**: не нужно писать
«что там». Длинные сообщения со ссылкой-источником не трогаются — модель сама
вызовет инструмент, если содержимое действительно нужно. Авто-чтение
выключается через `!set auto_links false`, число ссылок — `!set auto_links_max 2`
(1–3).

Для YouTube он достаёт название, автора, длительность и **субтитры** (сначала
русские, потом английские), поэтому можно спросить «о чём это видео» и
получить ответ по содержанию, а не по названию. Субтитры берутся через
`youtube-transcript-api` (работает там, где прямой `timedtext` отдаёт пустой
ответ) или напрямую из плеера; если оба источника недоступны — остаётся
описание видео.

Если страница не открылась (YouTube не пустил датацентровый IP Render, сайт
ответил ошибкой), используется **предпросмотр ссылки от Discord**: заголовок,
канал и описание. Модель ответит по ним и не будет делать вид, что ссылки не
было. Неудачная попытка видна в debug-строке как `fetch_url(…) ⨯ [авто]`.

Ограничения: только `http/https` и порты 80/443; локальные и внутренние адреса
запрещены, каждый редирект проверяется заново; тело страницы — до 3 МБ, текст
для модели — до 6000 символов; таймаут — около 12 секунд. Бинарные ответы
(PDF, архивы) отклоняются. Если YouTube не отдал субтитры (бот-проверка,
consent, музыка без речи), бот честно ответит по описанию видео. Страницы,
которые рисуются только JavaScript, вернут «нет читаемого текста».

Отключить инструмент: `!set enabled_tools '["web_search"]'`.

### Reddit-треды

Для ссылок `reddit.com/r/.../comments/...` используется отдельный
`read_thread`, а не `fetch_url`: Reddit отдаёт HTML с JavaScript и часто
блокирует `.json`, поэтому бот читает **RSS-ленту треда**, разбирает пост и
комментарии через `defusedxml`, выбрасывает `[deleted]`/пустые и делает
адаптивное обобщение.

- До 500 комментариев или 80 000 символов текста.
- Сначала один вызов модели; для больших тредов — 2–3 части + финальная сборка.
- Если отдельная часть не обработалась (503 у провайдера), остальные части всё
  равно идут в итог, а в ответе появляется пометка, что часть комментариев
  пропущена. Повторный вызов `read_thread` в том же ответе блокируется.
- Два RSS-хоста: `www.reddit.com` и `www.redditmedia.com`. Если первый отдал
  429/403, бот пробует второй; между запросами — пауза 3 секунды.
- Успешно прочитанные треды кэшируются в памяти на час, недавние неудачи — на
  60 секунд, чтобы не долбить Reddit повторно.
- Длина ответа определяется содержанием: простой тред — 2–4 предложения,
  сложный — разделы и аргументы, но без пересказа каждого комментария.
- Итог до 12 000 символов. Ссылка на исходный тред добавляется в «Источники»
  всегда — даже если RSS или обобщение не удалось.
- Reddit-ссылка вызывает `read_thread` принудительно, чтобы не получить
  обрезанный огрызок из `fetch_url`.
- Если оба RSS-хоста недоступны (403/429/пусто), бот честно скажет об этом и не
  будет подменять обсуждение результатами `web_search`.

### Честная память действий бота

Каждый ход сохраняет в `messages.metadata` фактический трейс: модель, все
вызовы инструментов с аргументами (например, поисковый запрос) и число
источников. На следующем ходе этот трейс возвращается модели блоком
`<bot_last_actions>`, поэтому вопрос «какой запрос ты использовал для поиска?»
больше не ловит модель врасплох: она отвечает реальными действиями, а не
выдумкой. Отдельный `!set debug_mode true` показывает после каждого ответа
одну строку (`-# 🛠 …`) с моделью, инструментами и размером контекста —
те же цифры всегда есть в логах, даже при выключенном debug.

### Режим «чистого ответа»: `/c`

Добавь `/c` в конец сообщения — бот ответит фактами и структурой, без
личности и обращений, но с полным контекстом диалога. Алиас: `/clean`.
Маркер вырезается из истории памяти и не останется в транскрипте. Работает
и с `/c` в ЛС, и в разрешённых каналах; обычные ответы не затрагивает.
URL вида `https://example.com/c` режим не включают.

### Веб-поиск и фактчек

`web_search` умеет не только искать, но и ограничивать результаты по дате:

- `max_results` — 1–10; модель выбирает 3 для быстрого факта и 5–8 для
  обзора или фактчека. Если число не указано, берётся `search_max_results`
  (по умолчанию 5).
- `time_range` — `day`, `week`, `month`, `year`; для явного периода —
  `start_date`/`end_date` в формате `YYYY-MM-DD`.
- `topic=news` — для свежих новостей; `published_date` возвращается и
  показывается в результатах.
- При явном периоде включается строгая фильтрация по дате публикации:
  страницы без определяемой даты отбрасываются.
- `deep=true` — advanced-поиск (2 кредита Tavily) только по явной просьбе
  о глубоком исследовании; обычный поиск — 1 кредит, число источников на
  стоимость не влияет.

Промпт инструмента требует формулировать запрос 2–6 ключевыми словами,
точные названия и цитаты — в кавычках, а для фактчека — проверяемое
утверждение, 3–5 источников, сравнение дат/первоисточников и явное разделение
подтверждённого и неподтверждённого.

Текущая дата всегда передаётся модели в блоке `<current_datetime>`; она
считается источником истины, а не знания модели. «Свежие/последние» новости
ищутся через `time_range`, точная дата — через `start_date`/`end_date`.
Год в query допустим, если пользователь явно его назвал; запрос с несколькими
устаревшими годами без явного исторического контекста отклоняется до вызова
Tavily, чтобы не тратить кредит на заведомо неверные результаты.

### Рисование схем и иллюстраций

Попроси нарисовать схему, диаграмму, график, иконку или иллюстрацию — бот
сгенерирует SVG отдельным вызовом модели, проверит его и пришлёт **PNG**:
Discord не показывает SVG инлайн, поэтому исходник прикрепляется только если
явно попросить «svg», «вектор» или «исходник» — или поставить `/svg` в конец
сообщения: `нарисуй краба /svg`. Маркер вырезается из памяти, как `/c`, и
работает в любом порядке с `/c`: `нарисуй схему /c /svg`.

- Модель для рисунков: `svg_model` (по умолчанию — текущая модель бота),
  отдельный `max_tokens` до 4096, поэтому длинные схемы не обрезаются.
- Ограничения: SVG ≤ 100 КБ и ≤ 300 элементов; PNG ≤ 3 МБ, ширина 1200 px.
- Безопасность: `defusedxml`, запрет `script/style/foreignObject/image`,
  обработчиков `on*`, внешних ссылок и `url(http…)`.
- Шрифты DejaVu Sans лежат в `discord_bot/assets`, поэтому подписи рисуются
  одинаково на Render и локально.
- Пауза между рисунками одного пользователя — `svg_cooldown_seconds`
  (по умолчанию 15 секунд), чтобы не выжигать лимит Gemini.
- Отключить: `!set enabled_tools '["web_search","fetch_url"]'`.

**Пиксель-арт.** Попроси «нарисуй краба в пиксель-арт» или добавь `/pixel`
в конец сообщения. SVG-модель сразу рисует на нативной сетке, а в ответ
приходят два файла: **128×128** (первым, для превью) и исходная сетка
**16/32/64/128** (например, 32×32). Формат:

- `/pixel` — сетка из `pixel_grid` (по умолчанию 32);
- `/pixel 64` — сетка 64×64;
- `/pixel:gameboy` — текущая сетка + палитра;
- `/pixel 64:gameboy` — сетка 64 + палитра gameboy;
- `/pixel 64 /svg` — 128 PNG + 64 PNG + SVG.

Сетка — только 16, 32, 64 или 128: тогда второй PNG всегда ровно 128×128.
`pixel_grid` и `pixel_colors` настраиваются через `!set`.

**Палитры.** Хранятся в Supabase (`bot_settings` → `pixel_palettes`), поэтому
их можно добавлять и удалять без деплоя. Встроенные: `pico8`, `gameboy`,
`sweetie16`, `cga`, `mono`, `sepia`. Управление в ЛС владельца:
`!palette list`, `!palette show gameboy`, `!palette add mine #112233 #445566`,
`!palette remove mine`, `!palette reset`. Выбор на запрос:
`/pixel:gameboy` или `/pixel 64:gameboy`; глобально — `!set pixel_palette gameboy`.
Неизвестная палитра даёт понятную ошибку со списком доступных. Сначала палитра
передаётся модели в промпте, затем каждый пиксель нативной сетки заменяется на
ближайший цвет палитры, и только после этого делается nearest-апскейл до
128×128.

`/pixel` совместим с `/c` и `/svg` в любом порядке. Работает только для
рисунка, созданного в этом же запросе: прошлые PNG бот не хранит.

### Улучшение присланного SVG

Прикрепи `.svg` (до 100 КБ) и напиши, что улучшить — «сделай аккуратнее»,
«перерисуй в тёмной теме», «исправь стрелки». Бот прочитает исходник как
недоверенные данные, передаст его SVG-модели и пришлёт **PNG + улучшенный
SVG** (исходник в этой ветке приходит всегда).

- `defusedxml`, лимит 100 КБ, запрет скриптов, обработчиков, внешних ссылок и
  встроенных растровых `<image>`.
- Безопасный `<style>` разрешён (Figma/Illustrator-экспорты проходят), но
  `@import`, внешние `url(...)` и `javascript:` отклоняются.
- Исходный файл никогда не рендерится напрямую — только проверенный ответ
  модели.
- В память попадает пометка `[svg-вложение: имя]`, не содержимое.
- Срабатывает на «улучши/перерисуй/исправь/доделай…»; на «что это за svg?»
  принудительного улучшения нет.

### Изображения

Бот принимает картинки из текущего сообщения (`png`, `jpeg`, `webp`, `gif`):
до **2** изображений, каждое до **8 МБ**. Они уходят в модель как vision-части,
поэтому `gemini-3.5-flash-lite` может описать скриншот или ответить по схеме.
В память и в Supabase попадает только текстовая пометка `[изображение: имя]`,
сами файлы не сохраняются; PDF, видео и архивы игнорируются. Слишком большой
или битый файл не ломает ответ — бот просто отвечает текстом с пометкой.

### Справка: `!help` и `/help`

`!help` в любом канале (и текстовый `/help` — как обычное сообщение) печатает
актуальный список команд. Справка строится из реально зарегистрированных
команд: новая команда не может «потеряться» в справке. Отладочные команды
владельца видны всегда, работать будут только в личных сообщениях владельца.

При веб-поиске бот добавляет в ответ блок **«Источники»** с реальными URL из
результатов Tavily. Ссылки, которые модель уже указала в тексте, повторно не
добавляются; embed-превью подавляются.

## Ошибки модели

Ошибки провайдеров классифицируются:

- `404` — модель не найдена; бот подсказывает ближайший ID и предлагает `!models`;
- `401/403` — проблема с API-ключом;
- `429` — исчерпан лимит free-тарифа, показывается `Retry-After`;
- `400/422` — провайдер отклонил запрос (например, модель не поддерживает tools);
- `5xx`/timeout — провайдер временно недоступен;
- неизвестные — короткий `error_id` для поиска по логам.

В консоль пишутся провайдер, модель, статус, тип ошибки, `base_url` и
безопасно обрезанное описание без API-ключей.

## Как добавить инструмент

1. Создай модуль в `discord_bot/tools/`, например `weather.py`.
2. Экспортируй `create_tool()`, возвращающий `Tool`:

```python
from discord_bot.tools.base import Tool, ToolContext

def create_tool() -> Tool:
    async def handler(context: ToolContext, city: str) -> str:
        return f"Погода в {city}: ..."

    return Tool(
        name="weather",
        description="Возвращает погоду в городе.",
        parameters={
            "type": "object",
            "properties": {"city": {"type": "string"}},
            "required": ["city"],
        },
        handler=handler,
    )
```

3. Перезапусти бота — модуль загрузится автоматически.
4. Включи его командой `!tools enable weather`.

## Деплой

### Точки входа

- `python main.py` — production entrypoint, его использует текущий Render.
- `python -m discord_bot` — альтернативный запуск.
- Оба варианта вызывают `discord_bot.main.main()`.

### Render

В репозитории есть `render.yaml` (Blueprint) и `.python-version` с `3.11.9`.

Если сервис уже создан вручную, достаточно проверить:

- **Python**: `PYTHON_VERSION=3.11.9` или `.python-version`.
- **Build command**: `pip install -r requirements.txt`.
- **Start command**: `python main.py` — обновите его в Render.
- **Health check path**: `/healthz`.
- **Instance count**: `1`, иначе несколько копий бота будут дублировать ответы.
- **Env vars**: `DISCORD_TOKEN`, `SUPABASE_URL`, `SUPABASE_KEY`, ключи нужных
  LLM-провайдеров и `TAVILY_API_KEY`.
- **PORT** не задавать вручную — Render передаёт его сам.

Секреты в `render.yaml` помечены `sync: false`, их нужно заполнить в Dashboard.
Health-сервер слушает `0.0.0.0:$PORT`.

### Docker

```bash
docker build -t discord-ai-bot .
docker run --env-file .env -p 7860:7860 discord-ai-bot
```

Образ работает от непривилегированного пользователя и имеет HEALTHCHECK на
`/healthz`. Внутри контейнера `PORT` можно переопределить:

```bash
docker run --env-file .env -e PORT=8080 -p 8080:8080 discord-ai-bot
```

### Защита от 429 при деплое

Render free поднимает новый инстанс, пока старый ещё держит Discord gateway.
Два логина почти одновременно дают глобальный `429`, поэтому добавлены два
предохранителя:

- **Heartbeat-ожидание.** Перед логином новый инстанс читает
  `instance_heartbeat` из Supabase. Если heartbeat другого процесса свежий
  (< 180 секунд), он ждёт, пока старый инстанс остановится и heartbeat остынет.
  В `/healthz` это состояние `waiting_previous`.
- **Persistent login-gate.** При `429` дедлайн (`login_blocked_until`) пишется
  в `bot_settings` вместе с хэшем текущего токена. После рестарта или нового
  деплоя процесс ждёт этот дедлайн, а не долбит Discord заново. После успешного
  логина ключ очищается; при сбросе токена хэш не совпадает, и старый блок
  игнорируется. В `/healthz` это состояние `waiting_login`.

Оба механизма не требуют новых env-переменных; ключи служебные и скрыты из
`!settings`.

  дополнительно применить `20261108000200_fix_ingest_message.sql` и
  `20261108000300_fix_history_before.sql`.
- Задать `allowed_channel_ids` для двух каналов через `!set`.
- **Render start command**: `python main.py`. Если используется `render.yaml`,
  он уже обновлён.
- **Python**: закрепить 3.11+ через `.python-version` или `PYTHON_VERSION`.
- **Health check**: путь `/healthz`.
- **UptimeRobot**: пинговать
  `https://discord-bot-nmc8.onrender.com/healthz` раз в 5 минут.
- **Instance count**: `1`, чтобы не было дублирующих ответов.
- **Docker**: обновить `COPY` и `CMD`, если используется свой Dockerfile.
- **Импорты**: пакет `bot` переименован в `discord_bot`; внешние скрипты,
  импортирующие `bot.*`, нужно обновить.
- **Локальный запуск**: `python main.py` или `python -m discord_bot`.
